Offizielle Validierung

        
Was ist KoSIT und warum nicht einfach Server?

        
KoSIT ist der offizielle lokale Validator-Stack für XRechnung: ein Java-Validator plus XRechnung-Konfiguration mit XSD, Schematron, Codelisten und Szenarien. Er prüft, ob eine konkrete XML-Rechnung die XRechnung-Regeln erfüllt und erzeugt einen Report.

        
In diesem Produkt hostet GitHub nur die statischen Dateien. Der Browser kann XML erzeugen, eingebettetes PDF-Rechnungs-XML/Text lokal auslesen und Browser-Sanity-Checks ausführen. Ein echter KoSIT-PASS wird erst behauptet, wenn der offizielle Validator auf dem Gerät des Benutzers für genau dieses XML gelaufen ist. Eine direkte Java-KoSIT-Portierung in den Browser ist theoretisch möglich, aber schwergewichtig; pragmatischer ist zuerst ein browsernativer Validator mit XSD/WASM, Schematron/XSLT, Codelisten und KoSIT-CLI-Paritätskorpus.

        
Browser-Validierung Zielbild: Die Webseite soll XSD per WebAssembly, Schematron/XSLT im Browser und Codelisten aus dem XRechnung-Bundle lokal ausführen. Ein KoSIT-CLI-Referenzvergleich bleibt der Goldstandard, bis der Browser-Report nachweisbar dieselben Entscheidungen trifft. Erst dann wird aus Browser-Sanity eine echte browserlokale XRechnung-Validierung.

Datenschutzmodell

      
Rechnungsdaten verlassen das Gerät standardmäßig nicht.

      
    
        
  • Keine Datenbank, keine Cookies, kein Tracking.
    • 
        
  • Keine Netzwerk-API im Generator-Code.
    • 
        
  • Lokale Dateiauswahl liest TXT/CSV/XML, eingebettetes PDF-Rechnungs-XML und einfachen eingebetteten PDF-Text nur im Browser-Tab.
    • 
        
  • Local review funnel and field-priority behavior: source file or form entry → local recognition → red/yellow/white field review → browser validation → export.
    • 
        
  • Production gap still visible by design: full KoSIT-equivalent browser validation, native PDF/A-3 assembly, robust OCR/DOC/DOCX extraction and every conditional BT/BG export mapping need local engines/parity tests before legal/compliance-grade claims.
    • 
      

      
Für andere Agenten/LLMs steht window.XInvoice.convertForAgent(invoice, formatId) bereit. Die API gibt strukturierte Fehler zurück, statt bei unvollständigen Daten still Artefakte zu bauen.
