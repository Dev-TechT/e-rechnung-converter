Offizielle Validierung

        
Woher bekommt man KoSIT?

        
KoSIT besteht aus zwei Teilen: dem Validator-Programm und der XRechnung-Konfiguration. Beides liegt öffentlich auf GitHub. Für XRechnung muss beides zusammen lokal ausgeführt werden.

      

      

        

          
1 · Validator

          
github.com/itplr-kosit/validator

          validator-1.6.2-standalone.jar
          Direktdownload
        

        

          
2 · XRechnung-Konfiguration

          
github.com/itplr-kosit/validator-configuration-xrechnung

          xrechnung-3.0.2-validator-configuration-2026-01-31.zip
          Direktdownload
        

        

          
3 · Visualisierung

          
github.com/itplr-kosit/xrechnung-visualization

          xrechnung-3.0.2-visualization-2026-01-31.zip
          Direktdownload
        

      

      
curl -L https://github.com/itplr-kosit/validator/releases/download/v1.6.2/validator-1.6.2-standalone.jar -o validator-1.6.2-standalone.jar
curl -L https://github.com/itplr-kosit/validator-configuration-xrechnung/releases/download/v2026-01-31/xrechnung-3.0.2-validator-configuration-2026-01-31.zip -o xrechnung-config.zip

      
ZUGFeRD/Factur-X zusätzlich lokal prüfen mit Mustangproject und veraPDF. Diese Browser-Seite führt nur schnelle Strukturchecks aus; offizielle Gültigkeit entsteht erst nach lokalem Validator-PASS.

    


    

      
Datenschutzmodell

      
Rechnungsdaten verlassen das Gerät standardmäßig nicht.

      
    
        
  • Keine Datenbank, keine Cookies, kein Tracking.
    • 
        
  • Keine Netzwerk-API im Generator-Code.
    • 
        
  • Lokale Dateiauswahl liest TXT/CSV/XML nur im Browser-Tab.
    • 
        
  • PDF/DOC/DOCX werden nicht hochgeladen; Desktop-Extraktion folgt als lokales Modul.
    • 
      

      
Für andere Agenten/LLMs steht window.XInvoice.convertForAgent(invoice, formatId) bereit. Die API gibt strukturierte Fehler zurück, statt bei unvollständigen Daten still Artefakte zu bauen.
