Offizielle Validierung

        
Was ist KoSIT und warum nicht einfach Server?

        
KoSIT ist der offizielle lokale Validator-Stack für XRechnung: ein Java-Validator plus XRechnung-Konfiguration mit XSD, Schematron, Codelisten und Szenarien. Er prüft, ob eine konkrete XML-Rechnung die XRechnung-Regeln erfüllt und erzeugt einen Report.

        
In diesem Produkt hostet GitHub nur die statischen Dateien. Der Browser kann XML erzeugen und Sanity-Checks ausführen; ein echter KoSIT-PASS wird erst behauptet, wenn der offizielle Validator auf dem Gerät des Benutzers für genau dieses XML gelaufen ist. Eine Browser-Portierung wäre möglich, aber sie muss Java/WebAssembly, ZIP-Artefakte, Schematron/XSLT und Report-Dateien sauber paketieren.

        
Browser-Validierung Zielbild: Die Webseite soll XSD per WebAssembly, Schematron/XSLT im Browser und Codelisten aus dem XRechnung-Bundle lokal ausführen. Ein KoSIT-CLI-Referenzvergleich bleibt der Goldstandard, bis der Browser-Report nachweisbar dieselben Entscheidungen trifft. Erst dann wird aus Browser-Sanity eine echte browserlokale XRechnung-Validierung.

Datenschutzmodell

      
Rechnungsdaten verlassen das Gerät standardmäßig nicht.

      
    
        
  • Keine Datenbank, keine Cookies, kein Tracking.
    • 
        
  • Keine Netzwerk-API im Generator-Code.
    • 
        
  • Lokale Dateiauswahl liest TXT/CSV/XML nur im Browser-Tab.
    • 
        
  • PDF/DOC/DOCX werden nicht hochgeladen; OCR/PDF-Extraktion läuft nur über eine lokale Browser-Engine oder ein lokales Desktop/CLI-Modul und bleibt prüfpflichtig.
    • 
      

      
Für andere Agenten/LLMs steht window.XInvoice.convertForAgent(invoice, formatId) bereit. Die API gibt strukturierte Fehler zurück, statt bei unvollständigen Daten still Artefakte zu bauen.
